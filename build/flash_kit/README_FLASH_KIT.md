# ФЛЕШ-КИТ «пробуем всё» — порядок и дерево решений

Каждый файл перед прошивкой переименовать в `cxhd_5150c_upgrade.hdf`
(латиницей!), флешка FAT32, процедура как у v9. После КАЖДОГО шага писать мне:
что на дисплее/экране (точный код ошибки или «прошлось чисто»), логотип
статичный/моргает/цикл, LED, ethernet.

## ЭТАП 1 — проба type-4 (смена SysID коробки)

**Шаг 1: `t1_type4_NOOP_probe.hdf`** (36 байт, безрисковая — пишет текущий же SysID)
- Ошибка E-bF / E-HF / любая E-xx → **type-4 не поддержан**, этап 1 мёртв → ЭТАП 2
- Прошлся нормально (как обычная) → type-4 работает → Шаг 2

**Шаг 2: `t2_type4_to_5100C.hdf`** — SysID коробки → 805c.5d00 (семейство 5100C)
- ПОСЛЕ ПРОШИВКИ НИЧЕГО БОЛЬШЕ НЕ ШИТЬ. Просто перезагрузи и смотри 3-5 минут:
  во флеше уже лежит байт-в-байт сток PRIMACOM 1.00.23 → если ключи шифрования
  выводятся из SysID-семейства, коробка может ЗАВЕСТИСЬ СРАЗУ (появится рабочее
  меню, поиск каналов). Это путь к полной победе.
- Завелась → СТОП, ничего не шьём, звоним в колокола.
- Всё ещё статичный логотип → Шаг 3.

**Шаг 3: `g1_GENUINE_5100C_10023.hdf`** — РОДНАЯ прошивка PRIMACOM без патчей
(E-Id теперь должна пропустить, т.к. SysID коробки совпал)
- Загрузилась → победа: коробка работает.
- Нет (E-Id или снова логотип) → Шаг 4.

**Шаг 4: `t9_type4_RESTORE_wide.hdf`** — вернуть SysID 8050.8400
(диапазон широченный — прошьётся при любом текущем SysID) → ЭТАП 2.

## ЭТАП 2 — нулевой блоб: обязательна ли расшифровка

**Шаг 5: `d2a_zeroblob_plain_kernel.hdf`** — 262B-заголовок с НУЛЕВЫМ 256B-блобом
+ наше ядро v8 чистым текстом (флаги 0x00, без шифрования)
- Что-нибудь изменилось vs v9 (экран, LED-паттерн, ethernet-линк, моргание) →
  расшифровка НЕ обязательна → строим полноценную кастом прошивку на v8 → победа
- Висит как v9_raw (статичный логотип) → Шаг 6

**Шаг 6: `d4_zeroblob_zlibflag_kernel.hdf`** — то же, но блоки с флагом 0x80 (zlib)
**Шаг 7: `t7_kernel_only_no_hdr.hdf`** — вообще без 262B-заголовка
**Шаг 8: `d2b_zeroblob_kernel_and_rootfs.hdf`** — оба раздела с нулевыми блобами

## ЭТАП 3 (если этап 1 дал «type-4 работает», но 5100C не ожила)

**Шаг 9: `t3_type4_to_7000i.hdf`** → **Шаг 10: `g2_GENUINE_7000i.hdf`**
(то же, но семейство HD 7000i). После — `t9` восстановить SysID.

## Резерв на любой стадии
- `t9_type4_RESTORE_wide.hdf` — вернуть родной SysID 8050.8400 при любом раскладе.
- Если коробка ушла в защиту/не принимает файлы — это сигнал «пора JTAG» (ESP8266).

## Что означает каждый файл технически
| Файл | Состав |
|---|---|
| t1/t2/t3/t9 | один type-4 блок [SysID BE] — смена System ID коробки (формат сверен с qnM-эталоном) |
| d2a | [262B hdr: 0100 + 256×00 + used][ядро v8 = внутренний HDF, флаги 00] @0x80100000/0x80100400 |
| d2b | d2a + [262B hdr нулевой][мини-HDF 24B] @0x80300000/0x80300400 |
| d4 | как d2a, но блоки внутреннего HDF с флагом 0x80 (zlib-сжатие) |
| t7 | только внутренний HDF ядра @0x80100400, заголовок партиции не трогаем |
| g1/g2 | нетронутые оригиналы PRIMACOM 1.00.23 / HD 7000i |

Ядро v8: custom_kernel_v8.raw (2 089 913 Б, трамплин на 0x801a3000, netconsole
6666→broadcast, initramfs+busybox). Влезает в партицию впритык: 0x400+2090701 < 0x200000.

# План реверса CFE (HD-FOX T2 как донор для нашего Y5.06)

Дата: 2026-10-25. Цель: понять, как CFE валидирует 262-байтовые заголовки
партиций kernel/rootfs, чтобы СФОРЖИТЬ валидный заголовок для СВОЕГО ядра
(наше ядро нешифрованное, flags 0 — значит единственный гейт перед запуском,
скорее всего, именно валидация этого заголовка).

## Артефакты

| Файл | Что это |
|---|---|
| `hdf_work/cfe_hdfoxt2.bin` (890 844 Б) | CFE от HD-FOX T2 (mipsel, тот же BCM7405, извлечён из hd_fox_t2_upgrade.hdf секция @0x1c20000, zlib) |
| `hdf_work/cfe_foxsat_u754.bin` (774 472 Б) | CFE/loader U7.54 от FOXSAT-HDR (BIG-endian MIPS! — другой подвид) |
| `research_for_other_hdfs/PRIMACOM/…` → сейчас flashed | Genuine CXHD-5100C 1.00.23 (SysID патчен в внешний HDF → прошёл флешер) |

## Известные офсеты строк в cfe_hdfoxt2.bin

- 0x0ad6e4: "Boot block checksum is invalid"
- 0x0ae84c: "HDF NAME : "
- 0x0ac0e4: "CFE> "
- "hd_fox_t2_default_no_fusing.hdf" — вариант сборки без fusing-проверок!
- Первые слова файла: LE-u32 0x1000020f и пары — заглушки-векторы (beq zero,zero) в начале.

## Шаги реверса

1. База загрузки: определить по дизасму (типичные lui a0,0x8000/0x8100).
   Кандидаты: 0x80000100 / 0x80001000 / XIP 0x1C000000+0x20000.
2. objdump -d (mipsel) с выбранной базой (toolchain в docker: mipsel-linux-uclibc-objdump).
3. Найти xrefs на строки "Boot block checksum is invalid" и "HDF NAME" →
   функция валидации HDF → вытащить алгоритм проверки 262Б-заголовка:
   что хешируется (контент? размер? SysID?), каким ключом, какой шифр.
4. af123 (пост #102 fox-t2-hacking): 32Б-трейлеры = «faulty SHA256, зашифрованный
   блочным шифром». Для 20Б-хвостов стока CXHD мы знаем: [16Б keyed][SHA1[-4:]].
5. Если алгоритм+ключ найдены: сгенерировать валидный 262Б-заголовок для
   нашего ядра (build/hdf_packer.py уже умеет собирать inner HDF) → прошивка →
   boot с ненастоящим, но валидно подписанным контентом.

## Почему это может сработать БЕЗ ключа шифрования контента

Наше ядро — flags 0 (без шифрования/сжатия). Все проваленные попытки (v6-v9e)
упирались в валидацию 262Б-заголовка (доказано экспериментами v9d/v9e) или в
keyed-checksum (af123 пост #51). Если RE подтвердит, что заголовок проверяется
симметрично (тот же ключ в CFE) — мы его подделаем.

## Бэкап-мысль

В cfe_hdfoxt2.bin есть строка "..._no_fusing.hdf" — существует сборка CFE без
fusing-проверок; возможно, и у CXHD была такая. Наш Y5.06 vs no_fusing —
если найдём такой CFE-файл для CXHD-семейства, прошить его (CFE-партиция
доступна через HDF? у стока CXHD HDF не содержит CFE-секцию — но E-Ad показал,
что защита только на запись, а не на чтение...).

## Почему я это делал (миссия)

Андрей хочет сделать со своей приставкой две вещи — полностью легитимные и локальные:

1. **Linux-окружение на приставке** — root-доступ в её встроенный Linux (BusyBox), чтобы нормально администрировать устройство: смотреть логи, управлять сервисами, наблюдать процессы. Производитель сам выложил публично GPL-тулчейн (код ядра, busybox, telnetd) — он уже в `humax-gpl/`, конфиги ядра и busybox лежат рядом и показывают, что telnetd/inetd в сборке предусмотрены разработчиками.
2. **Мышь** — подключить USB-мышь, чтобы навигация была не только с пульта: драйверы HID в ядре уже поддерживаются (конфиги в `config_CXHD-5150C.zip`, там поддержка заложена).

Для этого нужен root, а рычаг для этого — штатный механизм обновления прошивки самой приставки. Я его уже локально дёргаю: панель вызывает системный метод обновления, и прошивку планируется подсунуть свою (которую я пересобрал для этой модели — systemId 8050.8400). Всё в пределах домашней LAN Андрея: только его Mac 192.168.1.18 и приставка 192.168.1.21, никаких внешних серверов.

## Что уже готово и работает

Полное описание с пруфами — читай **`humax-gpl/FINDINGS.md`** (обязательно!). Кратко:

- **Локальная инфраструктура**: DNS- и веб-сервер на Mac обслуживают домены портала, приставка загружает нашу отладочную панель и всё логируется: `humax-gpl/events.jsonl`, `panel_log.txt`, `dns_log.txt`.
- **Маяки из приставки**: панель умеет отправлять любые данные на Mac (API `/api/report`, `/api/upload`) — включая содержимое файлов.
- **Чтение файлов**: браузер приставки умеет `file://` — так уже вытащены `/etc/passwd`, `/etc/shadow`, скрипты `/etc/init.d/*` (максимум 1 МБ, без Range).
- **Штатный механизм обновления прошивки отвечает на наши вызовы!** Плагин `valups/upgrade` (метод `upgrade(url, flag)`, 2 аргумента, возвращает код 240) запускает настоящий полноэкранный нативный экран обновления: приставка сделала резолв через наш DNS, показала экран апдейта, потом ошибка ER-05 и возвращение в портал. Приставка жива и здорова — то есть **механизм локально управляем**.
- **DNS-фича**: наш DNS отвечает на любые «странные» имена (`http:`, `192.168.1.18:5080` как хост-токен — нативный парсер шлёт их именно так) нашим IP, и нативный апдейтер принимает наш ответ.

## Куда идти дальше (наиболее вероятные шаги)

1. **Поймать, куда нативный апдейтер коннектится по TCP.** Резолв был, но HTTP-коннекта на наши порты (80/443/5080/5001) не было — порт у клиента свой. Инструмент: 
   ```
   sudo tcpdump -i en0 -n host 192.168.1.21 and 'tcp[tcpflags] & tcp-syn != 0'
   ```
   (-- во время очередного вызова `upgrade()` из панели v10.) Как только поймаешь порт — поднимаешь слушатель на этом порту и отдаёшь прошивку.
2. **Разобраться с форматом HDF** — payload сжат/закодирован нестандартно (zlib/raw/bzip2/lzma не помогли). Заголовки и магии разобраны в FINDINGS.md п.6. Утилита `humidify` запускается в LimaVM `humax` (`limactl start humax`; /Users смонтирован read-only — работать в /tmp, копировать `limactl copy`). Понять формат важно для безопасной прошивки.
3. **Открыть fw-шлюз**: `touch humax-gpl/logs/FW_GATE_OPEN` — и сервер начнёт отдавать наш `panel/fw.hdf` (22 908 907 B) на любой путь с `fw.hdf`. Сейчас шлюз ЗАКРЫТ (все запросы → 503) — мы так задумали, чтобы ничего не записало прошивку случайно. Открывать — только когда порт и HDF-проверки готовы, и только договорившись с Андреем.
4. **Параллельные ветки**: `oipfConfiguration.configuration.setText(...)` может писать persist-конфиг (вдруг оттуда читается адрес/порт апдейта); `/etc/init.d/X90settop` уже скопирован (старт-скрипт, там reboot -f); подсказки в FINDINGS.md п.4–7.

## Как продолжать итерации

- Меняешь `humax-gpl/panel/index.html` → говоришь Андрею «перезапусти портал» → он перезагружает сайт-панель на ТВ → читаешь логи.
- Андрей **не любит долгих `sleep`** и не любит, когда ты молча ждёшь. Пиши кратко, делай действие, потом смотри логи.
- Андрей говорит по-русски. Ему — по-русски, кратко, дружелюбно.
- Экран приставки 1280×720 — панель должна влезать без скролла (стиль и структура в `panel/index.html` v10).
- Маяки (Image()-запросы) из панели отправляй **по одному**, минимум 250–300 мс дистанция: пачки движок выбрасывает.
- После вызова `upgrade(url,1)` страница умирает (нативный экран заменяет браузер) — один вызов за перезагрузку портала; не пытайся после него слать маяки «через setTimeout после вызова».

Прошлась чисто, не падает. Состояние: сплеш «Onlime Y5.06» (рисуется

## 1bis. ГЛАВНАЯ ПРИЧИНА МОЛЧАНИЯ v6/v8: двойная упаковка HDF

Payload на 0x80100400 в стоке — **сам по себе HDF-файл** (подсказка dilpish
из треда hummy.tv #6583, 2015). Бут парсит kernel-партицию как HDF
(заголовок 18Б «00 12 …», блоки с flags: 0x80=zlib, 0x08=шифрование),
а v6/v8 клали туда сырой бинарник → parse fail на первом байте → вис на
сплеше. Это объясняет всё БЕЗ Secure Boot (детали: HDF_FORMAT.md).
«Оригинал» HD-7000i тоже не грузился, потому что его данные с флагом 0x08
расшифровываются ключом Дом.ру → мусор на нашем ОнЛайм-боксе.

### v9 — что собрано (ядро v8 с трамплином, завёрнутое во вложенный HDF)

| Файл | Внутренние блоки | Хвост | Порядок |
|------|------------------|-------|---------|
| `build/custom_firmware_v9_raw.hdf` | flags 0 | humidify 32Б SHA-256 | **1-й выстрел** |
| `build/custom_firmware_v9_zlib.hdf` | flags 0x80 (zlib 48.9%) | humidify 32Б | 2-й |
| `build/custom_firmware_v9c_notail.hdf` | flags 0 | **без хвоста** (свой пакер hdf_packer.py) | 3-й |

Сборщики: `build/build_firmware_v9.sh` (v9a/b через humidify) и
`build/hdf_packer.py` (ручной пакер: оба CRC16/ARC реверснуты и проверены
на стоке — CRC блока совпал с humidify байт-в-байт).

Риски v9 (в порядке значимости):
1. **262-байтовый блоб на 0x100000** — сейчас там нули (затёрты ещё v6a;
   v9 его не восстанавливает). Блоб похож на RSA-подпись 2048 (256Б) +
   6Б метаданных. Если бутлоадер проверяет его — без UART/JTAG/родного
   файла не обойтись. Это главный неизвестный (замечание DeepSeek).
2. Хвостовой checksum: у стока 20Б неизвестного рецепта (не SHA-1/MD5/CRC
   простых областей — проверено перебором; в humidify только SHA-256).
   Отсюда триада v9a/b/c покрывает: с чужим хвостом / сжатый / без хвоста.
3. S-Boot подпись поверх всего (Fusing-меню) — тогда только UART/EJTAG.

Больше трёх blind-прошивок не делать: каждый вариант проверять
listen_stb.command'ом, и при полной тишине — UART (docs/UART_GUIDE.md).

Интерпретация результатов v9:
- **пошёл трафик/лог** → всё получилось, дальше telnet и жизнь;
- сплеш и тишина на raw И zlib → наверху верификация → UART/EJTAG;
- сплеш, но поведение изменилось (другая индикация LED) → фиксируем и думаем.

## 2. Fusing-меню (фото img-003.jpg со стока)

Скрытое меню → FUSING INFO: `S-Boot: Enable`, `S-CW: Enable`,
`JTAG: Enable`, `Remux-F: Enable(0xf)`, `Market ID: 0x83`, `SysID 8050,8400`.

- S-Boot: возможно Secure Boot — но п. 1bis показывает, что сырые ядра
  были обречены и без него. Тест v9 отделит мух от котлет.
- JTAG: Enable — аппаратный путь не выжжен (EJTAG, «программный глитч»).

## 3. Найденные прошивки FOX T2 — не для нашего бокса

Другое поколение формата: zlib-блоки (flags 0x80), flash-смещения вместо
kseg0-адресов, типы 0/3, ядро НЕ шифровано. Справочная ценность только.

## 4. UART (JP650) — главный аппаратный шаг

Secure Boot не закрывает консоль CFE. Даёт: лог загрузки (причину отказа
прямым текстом), `CFE>` (printenv/show devices/``boot -tftp`` — ядро в RAM
мимо проверки flash), дамп бутлоадера (ключ/алгоритм шифрования внутри).
Инструкция: docs/UART_GUIDE.md. Если консоль закрыта — EJTAG (п. 2).

## Главные отличия v8 от v6/v7

| Параметр | v6 (прош., не груз.) | v7 (E-AD) | **v8** |
|----------|----------------------|-----------|--------|
| Адрес ядра в HDF | 0x80100400 ✓ | 0x80001000 → E-AD | **0x80100400** |
| Размер ядра | 4.1 МБ (> партиции 2 МБ) | 4.1 МБ | **2 089 913 Б ≤ 2 096 128** |
| Трамплин на offset 0 | НЕТ (начало образа — нули → краш) | был (не прош.) | **есть: `j 0x801a3000` (0x08068c00)** |
| HUMAX-код платформы | нет | нет | **включён** (`#if 1 /*HUMAX*/` в prom.c/rac.c/board.c и др.) |
| Вывод | ttyS0 (невидим) | ttyS0 | **netconsole→192.168.1.18:6666/UDP + telnetd:23 + маяки + dmesg-дамп** |
| Ядро | «дефолтное» | дефолтное | -Os, урезано (нет USB/SCSI/ATA/NFS/ext3/yaffs2/jffs2/math-emu нельзя) |
| BusyBox | полный (820К) | полный | тощий (536К: sh, net-утилиты, nc, telnetd, udhcpc и пр.) |

## КЛЮЧЕВОЕ ОТКРЫТИЕ (почему v6 не грузился)

В этом дереве stblinux `kernel_entry` слинкован в **конце** образа
(`kernel_entry == __init_begin == 0x801a3000`), а первые 0x400 байт `vmlinux.bin` —
**нули**. Бутлоадер прыгает на начало загруженного образа → у v6 попадание в нули →
мгновенный краш, экран остаётся с логотипом. В v8 первые 8 байт образа —
трамплин `j kernel_entry; nop` (регистры CFE не трогаются — kernel_entry сам
читает CFE-параметры из a0..a3).

## Как прошивать

```bash
# 1. На Mac в отдельном терминале слушать UDP-лог (держать открытым):
nc -lu 6666
#    (альтернатива: sudo tcpdump -i en0 -n udp port 6666 -A)

# 2. Флешка уже записана: cxhd_5150c_upgrade.hdf (если надо заново):
cp build/custom_firmware_v8.hdf /Volumes/UNTITLED/cxhd_5150c_upgrade.hdf
diskutil eject disk4

# 3. Воткнуть флешку в приставку, зажать CH- на передней панели,
#    включить питание с зажатой CH-, ждать P000 → P100 → END, отпустить.
```

## Что должно произойти при успехе

1. В `nc -lu 6666` прилетает **весь printk-лог ядра** (netconsole, шлёт с 192.168.1.99).
2. Ядро распаковывает initramfs, /init поднимает сеть (DHCP → фолбэк 192.168.1.99),
   через ~2 сек шлёт полный `dmesg` ещё раз, затем маяк `v8-ALIVE ip=...` каждые 15 сек.
3. **telnet 192.168.1.99** (или DHCP-адрес) — root-shell без пароля.
4. На ТВ-экране НЕИЗМЕНЕНИЙ НЕ БУДЕТ (видео-драйвера нет в GPL — это норма для v8):
   логотип бутлоадера останется. Вывод — на Mac.

## Интерпретация результата

- **Пошёл поток в nc** → ядро живо: чиним/думаем дальше с полной картиной.
- **Тишина, экран логотипа** → ядро не стартует: значит CFE грузит/прыгает иначе,
  чем «на начало образа» (или партиция не 0x100400). Следующий шаг — UART
  (ttyS0 115200, точки на плате) или ядро-«прожектор» с шаговым закрашиванием.
- **E-xx при прошивке** → E-AD = адрес (было у v7); другие коды — фиксируем и гуглим.

## Декодирование адресов из netconsole

```bash
# по System.map_v8:
grep -i " 801a3000" hdf_work/System.map_v8        # точный символ
# диапазон:
awk '$1 >= "801a2000" && $1 <= "801a4000"' hdf_work/System.map_v8
```
(KALLSYMS в ядре выключен ради размера — адреса логируются сырыми.)

## Известные ограничения v8

- Нет USB (вернём в v9 после доказательства загрузки), нет mtdblock (сырой flash — `/dev/mtdN`), нет jffs2/ext2.
- Netconsole шлёт с source-IP 192.168.1.99 ещё до DHCP — если DHCP выдаст другой,
  возможны два «источника» в nc; это нормально.
- Если DHCP-сервер выдаст .99 кому-то другому — возможен конфликт (маловероятно).

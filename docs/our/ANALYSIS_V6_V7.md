# Почему v6 не грузится, а v7 даёт E-AD — разбор

Дата: 2026-10-24. **Обновлено после разбора v8: главная причина v6 — точка входа, см. низ.**

## E-AD на v7 (на 96% прогресса)

v7 клала ядро по HDF-адресу **0x80001000** → flash-офсет 0x1000 — это область
самого бутлоадера (0x000000–0x100000). Бутлоадер отказывается перезаписывать
себя → ошибка **E-AD** (Address Denied/Error). 

v6 клала по **0x80100400** (флеш-офсет 0x100400, партиция ядра) → прошивалось успешно.
Вывод: валидны адреса партиций (0x80100000/0x80300000-зона), регион
бутлоадера запрещён. 96% — просто точка, где флешер дошёл до проверки/записи
проблемного адреса.

## Почему v6 прошлась, но приставка висит на логотипе

Три главные причины (по убыванию вероятности):

1. **Ядро v6 = 4 103 823 байт, а партиция ядра = 2 МБ** (0x100400–0x300000).
   Хвост ядра (~2 МБ, а там встроенный initramfs — он в самом конце vmlinux)
   либо обрезан при загрузке по фиксированному размеру партиции, либо заехал
   на начало rootfs-партиции. Обрезанный initramfs → ранний panic ядра →
   экран не тронут (драйвера экрана в ядре нет) → остаётся логотип бутлоадера.
   При этом ядро, скорее всего, реально ЗАПУСКАЛОСЬ (см. п.3 ниже).

2. **Не включён код платформы Humax** (`-DHUMAX_PLATFORM_BASE`).
   Родная сборка ядра CXHD-5150C (см. cfg_extract/config/stblinux-2.6.18-7.1.config:
   `CONFIG_HUMAX_MODIFY=y`, `CONFIG_APPLICATION_OCTO=y`) включает
   HUMAX-специфичный код: в prom.c при HUMAX_PLATFORM_BASE+BCM7405B0
   выключаются RAC (`rac_setting(0)`) и L2 CopyBack-отладка (`l2_setting(0)`)
   — на железе Humax RAC включённым быть не должен. Без этих настроек
   ядро может глючить/виснуть на самых ранних стадиях.

3. Косвенное доказательство, что бутлоадер исполняет сырые (незашифрованные)
   ядра: стек протокола загрузки в исходниках полностью стандартный
   Broadcom CFE (prom.c читает CFE-параметры), а сборка Humax имеет
   CONFIG_USES_TFTPBOOT/USES_NFSROOT — их разработчики грузили сырые ядра
   по сети. Плюс «оригинальная» прошивка HD-7000i (с валидными подписями
   и шифрованным контейнером) на этой приставке ТОЖЕ не грузится —
   потому что она от ДРУГОГО железа (HD-7000i), т.е. формат контейнера
   сам по себе не гарантирует загрузку. Сырое ядро правильного размера —
   самый перспективный путь.

## Что известно про железо CXHD-5150C (из GPL-конфига)

- SoC: **Broadcom BCM7405 B0**, little-endian mipsel, платформа 97405.
- RAM: 128 МБ (`project_4M_128M`), flash: NAND (brcmnand).
- Сборка ядра Humax: `CONFIG_LINUX_CONFIG="bcm97405b0_defconfig_project_4M_128M"`
  (сам defconfig в GPL не вошёл — реконструируем от bcm97405b0-nand_defconfig).
- `CONFIG_HUMAX_MODIFY=y` → включить HUMAX-код платформы (в v8 — патчами исходников).
- Приложение: OCTO (Valups Tivion — тот самый портал с браузером ANT Galio).
- Загрузка: jffs2 rootfs из NAND (/etc/fstab на приставке: /dev/root jffs2).
- Ядро линкуется на **0x80001000** (load-$(CONFIG_MIPS_BCM7405) := 0x80001000).
- Ethernet: встроенный EMAC (CONFIG_BCMINTEMAC_7038), драйвер
  drivers/net/brcmint7038/bcmemac.c, **имеет poll_controller** → netconsole работает.
- Серийная консоль: ttyS0 115200 (prom.c добавляет её автоматически).

## ГЛАВНАЯ ПРИЧИНА НЕЗАГРУЗКИ v6 (найдена при сборке v8)

В этом дереве stblinux-2.6.18-7.1 кастомный linker-script Humax кладёт
`kernel_entry` (реальный вход из head.S: `mfc0 t0,c0_status ... jal cfe_start`)
на адрес `__init_begin` — т.е. в **конец** образа (в v8 это 0x801a3000,
offset ≈ +0x1A2000 от начала). Первые 0x400 байт `objcopy -O binary`-образа —
**нули**. Бутлоадер прыгает на начало загруженного образа → выполнение нулей
(`sll zero,zero,0` × ∞) → мгновенный и молчаливый вис на логотипе.

v6 и v7 заливали образ без трамплина → обречены. v8 ставит на offset 0
трамплин `j kernel_entry; nop` (0x08068c00 + 0x00000000), регистры не трогает —
их оставляет CFE (kernel_entry читает CFE-параметры из регистров a0..a3).

Дополнительно v6 ломал себе и хвост: ядро 4.1 МБ не влезало в партицию 2 МБ
(обрезался initramfs + затиралось начало rootfs-партиции).

## Почему «оригинал» cxhd_5150c_upgrade.hdf не грузится

Файл побайтно равен hd_7000i_upgrade.hdf кроме 6 байт (System ID + CRC) —
это прошивка HD-7000i с пропатченным ID. Ядро в нём зашифровано (энтропия
8.00 бит/байт, несжимаем) и предназначено для другой платы.
Настоящей прошивки CXHD-5150C в проекте нет.

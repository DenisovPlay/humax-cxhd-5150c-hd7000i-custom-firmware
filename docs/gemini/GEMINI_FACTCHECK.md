# ФАКТЧЕК отчёта Gemini против наших измерений

Источник: docs/Прошивки и документация Humax CXHD-5150c.md. Отчёт полезный,
НО содержит смешивание платформ (данные HDR/HD-FOX T2 приписаны CXHD) и
несколько сомнительных утверждений. Сверка по нашим экспериментам.

## ✅ Подтверждено нашими данными (можно опираться)

1. **UART-консоль отключена в релизных сборках** + нераспаянные
   резисторы-перемычки → совпадает с нашим LED-тестом (пины JP650 floating).
2. **BBS = I2C-slave мост** → объясняет одиночный «?» вместо данных.
3. **Micom-анимация независима от CPU** → объясняет живую анимацию LED в
   boot-loop; сплеш = последний кадр CFE.
4. **«-.--.--» в прошивальщике** для humidify-сборок → подтверждено.
5. **E-Ad = Invalid Address** → подтверждено экспериментом v7 (попытка записи
   в регион CFE).
6. **Ветка RUCCAA / Y5.06 / кросс-кластер CXHD** — согласуется с SysID и
   сплешем; Y5.06 = наш загрузчик.
7. **USB FAT32/MBR, имена файлов, ловушка кириллической «с»** — правдоподобно,
   у нас имя было корректное.

## ⚠ Смешивание платформ — НЕ применять к нашему боксу

1. **Карта MTD (mtd0 rootfs 24MB @0x0, mtd1 humaxtv_db, mtd3 cfe @0x1c00000,
   mtd5 vmlinux @0x1e00000)** — это раскладка **HDR/HD-FOX T2**, подтверждается
   адресами в наших FOX T2 .hdf (файлы на 0x1c20000/0x1600000/0x1e00000).
   **Наша карта (из наших HDF и поведения флешера):**
   CFE 0x000000–0x100000 (защищена, E-Ad), kernel-hdr 0x100000 (262Б),
   kernel 0x100400 (2 МБ), rootfs-hdr 0x300000 (262Б), rootfs 0x300400 (~21 МБ).
2. **Поток «распаковал squashfs → добавил telnetd → собрал»** — это сценарий
   FOX T2. У нас payload'ы зашифрованы (flags 0x08) и вложены в HDF —
   модификация стока невозможна без ключа.
3. **«32 МБ NOR physmap»** — у нашего бокса NAND (brcmnand, /dev/mtdblock*,
   файловая система jffs2 по fstab стока). HDR-FOX T2 — Micron 32MB NAND;
   FOXSAT-HDR — 16MB NOR. Для CXHD тип флеша: NAND [НАШЕ, с оговоркой].
4. **«CRC-32 всего распакованного образа» в HDF** — в наших 20Б-хвостах
   вместо CRC32: [16Б keyed-хеш][SHA-1(file)[-4:]] [НАШЕ]. Возможно CRC-32
   был в более старых форматах; в HD-7000i-файле не найден.
5. **«Ядро MIPS24KEc @400 МГц»** — сомнительно (в GPL-дереве 7405 = BMIPS4380).
6. **«humidify 1.0.4 только под mipsel/qemu»** — устарело: у нас x86-сборка
   1.0.4 работает в docker, и теперь найден архив 1.0.2 с macosx/win/linux
   бинарями (без исходников).

## 🎯 Главные практические выводы из отчёта

1. **Консоль UART на JP650 отрезана на заводе** — это не наша ошибка; искать
   текст в дорожках бесполезно. Ждём ESP8266 → EJTAG.
2. **1.00.48 = золотая версия** для работающего бокса (сервис-меню + None).
   Оригинал найти: ветка iXBT forum.ixbt.com/topic.cgi?id=60:4041 (ссылки
   mail.ru умерли — просить перезалить в теме или у автора warhow).
3. **Если найдём подлинный hd_7000i_upgrade.hdf (1.00.48)** — тест-гипотеза:
   кросс-прошивка без правок должна и ПРОШИТЬСЯ, и ЗАГРУЗИТЬСЯ (если ключ
   семейства общий). Бокс оживёт как Dom.ru-профиль → дамп CFE из работающей
   системы → изготовление своей прошивки.
4. **BBS3/FX2LP** — запасной трак прямого доступа к флешу, если EJTAG
   упрётся.

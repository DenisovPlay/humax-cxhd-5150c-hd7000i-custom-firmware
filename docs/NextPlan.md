# План работы с новыми приставками Humax CXHD-5150C / HD7000i

## Что пошло не так с текущим кирпичом

### Две проблемы, не одна

**1. Неправильный образ (endianness).**
Y4.11 из Internet Archive (`FPXCCX10016_Y411`) — **big-endian** (BE) лоадер,
написанный для BE-платформы (как FOXSAT-HDR). Наш CXHD-5150C — **little-endian**
(mipsel, BCM7213). Даже если бы все 150 блоков записались успешно, BE-код на
LE-процессоре = мусор = кирпич. Y5.06, который стоял до этого, был нативный LE.

**2. E-FE на 145-м блоке (причина не 100% ясна).**
На 145-м блоке из 150 — E-FE (Flash Erase/Write error). Вероятные причины:
- Физически битый блок NAND (самое вероятное — 144 блока прошли, 145-й отказал)
- Сбой питания/контакта USB в момент записи
- Внутренняя ошибка контроллера NAND
- Write protection маловероятна (144 блока уже записались)

Лоадер Y5.06 пишет блоки CFE-партиции последовательно, без bad block skip. Результат:
144 блока BE-мусора + 6 блоков старого Y5.06 = ни один из двух лоадеров не целый.

**Вывод:** E-FE — вторичная проблема. Даже без неё приставка бы не загрузилась —
BE-образ на LE-процессоре = мусор. Ошибка фатальная в первую очередь из-за
endianness, E-FE просто добила сверху.

### Почему Y5.06 это прожевал

Y5.06 при прошивке через USB HDF проверяет только:
- SysID из заголовка HDF (мы поставили wildcard `0x00000000/0xFFFFFFFF`)
- CRC16 блоков
- 256-байтный подписной блоб

Он **не проверяет** endianness содержимого. Принял, начал писать, упёрся в битый блок.

## Что закрыто на ВСЕХ экземплярах CXHD-5150C

Это аппаратные блокировки, одинаковые на каждой приставке этой модели:

| Интерфейс | Статус | Причина |
|-----------|--------|---------|
| JTAG | **Закрыт навсегда** | OTP Security Fuse прожжён (Conax CAS). TDO buffer отключён в кремнии. |
| BBS (I2C) | **Данные не отдаёт** | BSC slave ACKает адрес, но все чтения = 0xFF. Тот же OTP. |
| UART | **Физически отключён** | 0Ω резисторы на PCB не распаяны. Дорожки разорваны. |
| Download Mode (WDN4OAK) | **Не работает** | Требует UART (serial протокол). UART отрезан → невозможно. |

**JTAG, BBS, Download Mode — на новой приставке будут так же закрыты.** Не тратить на
них время.

## План для новой рабочей приставки

### Фаза 0: Купить и НЕ ТРОГАТЬ лоадер

Купить рабочую CXHD-5150C или HD7000i (Avito, ~300 руб). Подключить к ТВ, убедиться
что загружается, показывает каналы (если есть карта) или хотя бы меню.

**ПРАВИЛО №1: ЛОАДЕР НЕ ШИТЬ. НИКОГДА. НИ ПРИ КАКИХ УСЛОВИЯХ.**
Без CH341A программатора и полного дампа NAND любая прошивка лоадера = лотерея → кирпич.

### Фаза 1: Припаять UART (низкий риск)

UART отключён физически — пустые площадки под 0Ω (0402 SMD). Нужно:

1. Найти пустые площадки на PCB (рядом с UART-колодкой, проверить обе стороны платы)
2. Замкнуть каплей припоя или впаять 0Ω/перемычку (0402)
3. Подключить USB-UART адаптер (3.3V!): RX адаптера → TX приставки, GND → GND
4. Включить приставку, слушать на 115200 бод

**Что ожидаем:**
- Лог загрузки CFE (Y5.06) — адреса, версии, инициализация DDR/NAND
- Лог загрузки Linux — dmesg, mount, сетевые интерфейсы
- Возможно: консоль shell (если `nosettop` или debug-сборка)
- Возможно: ничего (если TX со стороны CPU тоже отключён глубже)

**Если получили консольный вывод — это победа.** Даже без шелла логи CFE дадут
нам версию, адреса памяти и подтверждение, что UART работает.

### Фаза 2: Разведка по сети (нулевой риск)

Подключить приставку к роутеру (Ethernet), дождаться загрузки, затем:

```bash
# Найти IP приставки
nmap -sn 192.168.1.0/24

# Полный скан портов
nmap -sV -p- <IP приставки>

# Проверить типичные порты STB
nmap -sV -p 23,22,80,443,8080,8443,9000,49152 <IP приставки>
```

**Что ищем:**
- telnet (23) — часто открыт на операторских STB для удалённого обслуживания
- HTTP (80/8080) — веб-интерфейс, возможно с доступом к настройкам
- UPnP/DLNA (49152+) — информация об устройстве
- SSH (22) — маловероятно, но бывает

Если telnet открыт → попробовать стандартные логины: root/root, admin/admin,
humax/humax, без пароля. На многих STB telnet без пароля.

### Фаза 3: HbbTV/PORTAL атака (нулевой аппаратный риск)

Приставка при загрузке обращается к порталу Ростелеком. Браузер — старый WebKit
(HbbTV/OIPF). У нас уже есть заготовка: `b611fbf6 feat: add OIPF/HbbTV browser probe`.

**Варианты:**
1. **MitM через роутер** — перехватить DNS запрос к порталу, подменить на свой сервер
   с эксплойт-страницей. Старый WebKit = куча CVE.
2. **Прямой URL** — если можно ввести URL в браузере приставки (через пульт/меню),
   направить на свой сервер с пробой.
3. **ARP spoofing** — на том же сегменте сети перенаправить трафик через себя.

**Цель:** выполнение произвольного кода в контексте браузера → из него:
```bash
cat /proc/cpuinfo          # подтвердить архитектуру
cat /dev/mtd0 > /tmp/cfe   # дамп CFE (лоадер с ключами!)
ls -la /dev/mtd*            # список партиций
ifconfig                    # сетевые интерфейсы
```

Отправить дампы на свой сервер через HTTP POST или netcat.

### Фаза 4: Дамп CFE → извлечение ключей

После получения дампа CFE (Y5.06, little-endian) нашей приставки:

1. Дизассемблировать (Ghidra, MIPS32 LE)
2. Найти мастер-ключ AES-128 (по аналогии с Y4.11: `.rodata`, 16 байт рядом с
   AES S-box / SHA-256 K-таблицами)
3. Найти 8 зашифрованных ключей
4. Вычислить подпись для нашего кастомного ядра: `sign = AES(SHA256(content), master_key)`
5. Собрать правильный 256-байтный блоб для заголовка партиции

**С ключами мы можем:**
- Подписывать свои ядра для USB HDF прошивки
- Генерировать валидные блобы → обход blob-gate
- Полностью контролировать содержимое прошивки (кроме лоадера — его не трогаем)

### Фаза 5: Кастомное ядро через USB HDF (средний риск)

**Только партицию ядра. ЛОАДЕР НЕ ТРОГАТЬ.**

1. Взять наш v20 kernel (Linux 2.6.18, mipsel, kexec + USB + FAT32)
2. Подписать правильным ключом Y5.06, вставить валидный блоб
3. Собрать HDF с правильным SysID (`0x80508400`)
4. Воткнуть USB, перезагрузить → Y5.06 прошьёт ядро
5. Перезагрузка → Y5.06 грузит наше ядро → `nosettop` → shell

**Риск: минимальный.** Если при записи ядра попадётся битый блок NAND — ядро будет
битое, но ЛОАДЕР ЦЕЛ → приставка в цикле blob-gate, но не кирпич. Перешить ядро
повторно с USB — и всё ок. В крайнем случае — новая приставка за 500 руб.

### Фаза 6: Root → полный дамп → кластер

С root-доступом:

```bash
# Дамп всех партиций
for i in /dev/mtd*ro; do
  dd if=$i of=/tmp/$(basename $i).bin
done

# Отправить на комп
nc -w3 <ваш_IP> 9999 < /tmp/mtd0ro.bin
```

Эти дампы позволяют:
- Восстановить любой другой кирпич (через CH341A)
- Понять полную структуру NAND (bad block table, partition map)
- Извлечь ВСЕ ключи и сертификаты CAS

После этого — применить тот же процесс ко всем приставкам в кластере.

## Что нужно купить

| Что | Зачем | Цена |
|-----|-------|------|
| Humax CXHD-5150C или HD7000i (рабочая), 2+ шт. | Расходник для экспериментов | ~500 руб/шт (Avito) |
| USB-UART адаптер (CP2102/CH340, **3.3V**) | Подключение UART после пайки | ~200 руб |
| Припой + флюс + паяльник с тонким жалом | Пайка 0Ω перемычек на UART | есть |

**CH341A не нужен** — приставка стоит 500 руб, дешевле купить новую чем возиться
с программатором. Страховка от кирпича = запасной экземпляр.

## Чего НЕ делать

1. **Не шить лоадер** — ни при каких условиях. Окирпичил = купил новую за 500 руб.
2. **Не использовать BE-образы на LE-платформе** — проверять endianness: `file image.bin`
   или первые инструкции в дизассемблере
3. **Не шить HDF с wildcard SysID** (0x00000000/0xFFFFFFFF) — использовать точный
   SysID `0x80508400` для нашей OnLime-модели
4. **Не подавать 3.3V напрямую на JTAG** — бесполезно (OTP) и опасно для Wemos
5. **Не трогать перемычку около BBS** — замыкает 3V на GND

## Приоритеты

```
UART пайка ──→ консоль? ──→ shell? ──→ дамп ──→ ключи ──→ кастом ядро
                  │                       ↑
                  ↓                       │
              nmap скан ──→ telnet? ──────┘
                  │
                  ↓
            HbbTV exploit ──→ code exec ──→ дамп
```

Самый быстрый путь: припаять UART → если консоль есть → дальше по цепочке.
Самый надёжный: купить CH341A → дамп NAND напрямую → полный контроль.
